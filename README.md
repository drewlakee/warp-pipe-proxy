# Warp Pipe Proxy

Автоматическая настройка VLESS Reality на Ubuntu с помощью sing-box. Установщик генерирует учётные данные, настраивает DNS, firewall и службы, проверяет подключение и сохраняет ссылки для клиентов.

```text
       ______________
      |==============|     W A R P   P I P E
      |______________|     P R O X Y
         |  |    |
         |  |    |         YOUR SERVER. YOUR TUNNEL.
         |  |    |
         |  |    |         VLESS REALITY
         |_______|         Powered by sing-box
```

## Требования

- Ubuntu с работающим systemd и доступом root. Проверяется дистрибутив, без ограничения версии.
- Для обычного режима — установленный SSH-сервер: порты определяются через `/usr/sbin/sshd -T`. С `--container` SSH-сервер не требуется.
- Для обычного режима — права `NET_ADMIN`, доступные для записи сетевые sysctl и возможность управлять UFW через iptables/ip6tables. С `--container` эти требования снимаются.
- Доступ к APT-репозиториям, HTTPS и исходящим TCP/UDP 53 для рекурсивного DNS.
- Для подключения через интернет — доступный публичный IPv4 и открытые входящие TCP-порты прокси.

Первый запуск рассчитан на новый сервер: существующие каталоги sing-box, Unbound или fail2ban без маркера установщика приводят к отказу. В режиме `--container` каталог fail2ban не проверяется, поскольку эта служба не настраивается. Это не инструмент миграции чужой конфигурации.

На macOS скрипт напрямую не запускается. Podman на самом VPS не требуется; особенности контейнерного запуска описаны ниже.

## Быстрый запуск

1) На свежей VPS с root-пользователя

```bash
git clone https://github.com/drewlakee/warp-pipe-proxy.git
cd warp-pipe-proxy
./warp-pipe-proxy.sh install
warp-pipe-proxy client-qr
```


2) Скопируйте **весь каталог**, включая вспомогательные скрипты:

```bash
scp -r ~/Desktop/warp-pipe-proxy root@SERVER_IP:/root/
ssh root@SERVER_IP
cd /root/warp-pipe-proxy
bash warp-pipe-proxy.sh install
```

При входе обычным пользователем скопируйте каталог в его домашнюю папку и используйте `sudo bash warp-pipe-proxy.sh install`.

Установщик не задаёт вопросов. UUID, Short ID и ключи Reality генерируются автоматически. Успешный запуск завершается плашкой `DONE` и сообщением `SUCCESS`.

## Команды

Команда обязательна. Запуск без команды или только с `--container` выводит справку и завершается с кодом 2, не меняя систему.

Запускайте из каталога проекта на Ubuntu с systemd:

| Команда | Назначение |
| --- | --- |
| `sudo bash warp-pipe-proxy.sh install` | Установка или повторное применение настроек |
| `sudo bash warp-pipe-proxy.sh install --container` | Установка в контейнере без управления UFW, fail2ban и BBR |
| `sudo bash warp-pipe-proxy.sh check --container` | Проверка прокси и DNS без проверки UFW и fail2ban |
| `sudo bash warp-pipe-proxy.sh check` | Проверка конфигурации, служб, DNS и VLESS |
| `sudo bash warp-pipe-proxy.sh client-profile` | Вывод полного профиля sing-box из сохранённых настроек |
| `sudo bash warp-pipe-proxy.sh status` | Быстрый статус служб и порта |
| `sudo bash warp-pipe-proxy.sh doctor --url https://ya.ru/` | Сравнение прямого доступа и VLESS |
| `sudo bash warp-pipe-proxy.sh logs --follow` | Просмотр журнала в реальном времени |
| `sudo bash warp-pipe-proxy.sh client-config` | Вывод сохранённых ссылок подключения |

`client-config` читает `/etc/warp-pipe-proxy/clients.txt`, который создаётся после успешных проверок. Ссылки содержат данные доступа; команда не записывает их в журнал установщика.

## Что настраивается

| Компонент | Настройка по умолчанию |
| --- | --- |
| VLESS Reality | `0.0.0.0:10443`, UUID, flow `xtls-rprx-vision` |
| Unbound | DNS на `127.0.0.1:5353`, системный DNS не меняется |
| sing-box | Служба `warp-pipe-proxy`, непривилегированный пользователь `warp-pipe-proxy` |
| fail2ban | Защита SSH: 5 ошибок за 10 минут, блокировка на 1 час |
| UFW | Разрешения для обнаруженных SSH-портов и TCP-портов прокси |
| BBR | Необязательная оптимизация после успешной установки; пропускается в контейнере |

Пользователи SSH, пароли и настройки входа не меняются. Защищённый транспорт предоставляет VLESS Reality. Собственный домен и TLS-сертификат для VPS не требуются.

## Порядок установки

Ниже описан обычный режим. С `--container` действия с firewall, SSH-защитой и BBR пропускаются; подготовка прокси, DNS и проверки VLESS сохраняются.

1. Проверяются окружение и права firewall. Если необходимые инструменты уже доступны, проверяется доступ к правилам firewall до установки пакетов; иначе проверка повторяется после установки зависимостей.
2. Определяются SSH-порты. Перед включением ранее неактивного UFW проверяются внешние TCP- и UDP-listeners: допускаются SSH и порты, принадлежащие процессу управляемой службы. Проверка выполняется и при повторных запусках. При активном UFW этот запрет не применяется.
3. Создаются резервные копии, устанавливаются зависимости. При отсутствии sing-box он устанавливается из официального APT-репозитория; существующий бинарник используется без принудительного обновления.
4. Определяется публичный IPv4 через api.ipify.org с резервным checkip.amazonaws.com. Выбирается Reality-host из `www.microsoft.com` и `www.cloudflare.com` после проверки TLS 1.3, сертификата и ALPN h2.
5. Создаются настройки и учётные данные, если их ещё нет. При повторном запуске они сохраняются.
6. Во временном каталоге генерируются и проверяются конфиги sing-box, Unbound, fail2ban и unit systemd. Отсутствующий или пустой DNSSEC trust anchor создаётся из пакета `dns-root-data`; существующий непустой ключ сохраняется.
7. Создаётся снимок для отката, применяются конфиги и запускаются службы. Штатная служба `sing-box` отключается; прокси обслуживает `warp-pipe-proxy`.
8. Добавляются правила UFW без сброса существующих. Если UFW был выключен, задаётся `deny incoming / allow outgoing` и firewall включается.
9. Отдельно проверяется активность каждой службы, DNS по TCP/UDP. Временный клиент sing-box выполняет HTTPS-запрос через VLESS Reality с созданными данными доступа.
10. Сохраняются клиентские ссылки и итоговые настройки, завершается этап с откатом. Затем выполняется необязательная настройка BBR.

Установщик не выполняет полное обновление ОС и не перезагружает сервер. Он не настраивает firewall провайдера или маршрутизатор. Локальная проверка VLESS подтверждает работу протокола, но доступность снаружи нужно проверить отдельным клиентом.

## Логи и файлы на сервере

Все сообщения скриптов — на английском; для вызываемых команд устанавливается `LC_ALL=C`. Этапы отображаются без нумерации, с названием и временем UTC. В терминале этапы и `INFO` выделяются голубым, `SUCCESS` — зелёным, `WARN` — жёлтым, `ERROR` — красным. Уровни остаются в текстовом журнале; цвет добавляется после записи в файл. При перенаправлении вывода, `TERM=dumb` или заданном `NO_COLOR` подсветка отключается.

Стартовый баннер зелёный в поддерживаемом терминале; в файл журнала он записывается без цветовых кодов. Для отключения цвета используйте `sudo env NO_COLOR=1 bash warp-pipe-proxy.sh install`.

| Путь | Содержимое |
| --- | --- |
| `/var/log/warp-pipe-proxy-installer/ДАТА-PID.log` | Журнал запуска, этапы и ошибки |
| `/etc/warp-pipe-proxy/settings.json` | IP, Reality-host и порты |
| `/etc/warp-pipe-proxy/credentials.json` | Пароль, UUID и ключи; доступ только владельцу |
| `/etc/warp-pipe-proxy/clients.txt` | Ссылка VLESS |
| `/etc/warp-pipe-proxy/summary.json` | Настройки последнего успешного запуска без секретов |
| `/etc/sing-box/config.json` | Серверный конфиг, доступен root и группе warp-pipe-proxy |
| `/var/lib/warp-pipe-proxy-installer/ДАТА-PID/` | Начальная резервная копия |
| `/var/lib/warp-pipe-proxy-installer/ДАТА-PID/transaction/` | Снимок конфигов непосредственно перед применением |

Системные пути, служба, пользователь и группа используют имя `warp-pipe-proxy`. Резервные копии содержат секреты и хранятся в закрытом каталоге.

```bash
sudo systemctl status warp-pipe-proxy --no-pager
sudo journalctl -u warp-pipe-proxy -n 100 --no-pager
sudo journalctl -u warp-pipe-proxy -f
sudo ufw status numbered
```

Журнал работающего прокси ведёт journald с системной политикой хранения.

## Изменение настроек

Отредактируйте `/etc/warp-pipe-proxy/settings.json` и повторите установку. Порты VLESS и DNS должны быть различными целыми числами от 1024 до 65535 и не совпадать с портами SSH.

Для первого запуска можно переопределить публичный адрес и Reality-host:

```bash
sudo env VPS_PUBLIC_IP=YOUR_PUBLIC_IPV4 VPS_REALITY_HOST=YOUR_TLS_HOST bash warp-pipe-proxy.sh install
```

При наличии `settings.json` используются значения из файла, а не окружения. Поле `public_ip` сейчас принимает только публичный IPv4.

Секреты находятся отдельно в `credentials.json`. Не удаляйте этот файл для повторного запуска: после успешной установки его отсутствие считается ошибкой. Приватный и публичный ключи Reality меняйте парой.

При смене портов старые разрешения UFW сохраняются. Проверьте `sudo ufw status numbered` и удалите ненужные правила самостоятельно.

## Podman и подключение по Wi-Fi

Для контейнера используйте явный флаг:

```bash
sudo bash warp-pipe-proxy.sh install --container
sudo bash warp-pipe-proxy.sh check --container
```

Флаг можно указывать до или после команды. Его нужно повторять при каждом запуске установки или проверки: режим не сохраняется в настройках. Без флага выполняются обычные проверки прав firewall.

В этом режиме:

- UFW и fail2ban не устанавливаются, не настраиваются и не проверяются.
- Существующие правила firewall и служба fail2ban не отключаются; откат также их не затрагивает.
- BBR пропускается; запись сетевых sysctl и capability `NET_ADMIN` не требуются.
- SSH-сервер не требуется. Systemd, root, доступ к пакетам, DNS и интернету по-прежнему нужны.
- sing-box, Unbound, ссылки подключения и проверки VLESS работают как в обычном режиме.

Для этого режима не нужно добавлять `--cap-add=NET_ADMIN`, `--security-opt=unmask=/proc/sys` или `--privileged` ради установщика. Systemd должен быть настроен в образе и запущен как PID 1; один флаг `--container` этого не делает.

Установщик явно пишет в лог, что firewall и SSH-защита внутри контейнера не управляются. Ограничения доступа к опубликованным портам настраивайте на хосте. Существующий контейнер, запущенный с расширенными правами, не теряет их от этого флага: для уменьшения прав его нужно пересоздать.

Для подключения из локальной сети опубликуйте порты при создании контейнера:

```text
-p 0.0.0.0:10443:10443/tcp
```

Проверьте публикацию командой `podman port CONTAINER_NAME`. Эти параметры только публикуют порты и не обеспечивают остальные требования установщика.

В клиенте на телефоне укажите Wi-Fi IP ноутбука и опубликованный порт. Сгенерированные ссылки содержат публичный IP — для локальной проверки замените в них адрес сервера. SNI, UUID, public key и Short ID оставьте прежними. При отличающемся внешнем порте измените также порт подключения. Доступность зависит и от firewall ноутбука, и от настроек Wi-Fi.

После успешной установки создаётся полный профиль sing-box `/etc/warp-pipe-proxy/client-sing-box.json` с TUN и DNS через прокси; IPv4 и IPv6 разрешены. Заметки для отладки находятся в [debug/podman-debug.md](debug/podman-debug.md).

## Клиентский профиль sing-box

Для подключения импортируйте `/etc/warp-pipe-proxy/client-sing-box.json` в клиент sing-box. Профиль рассчитан на sing-box 1.12+; совместимость с конкретной версией приложения нужно проверить при импорте.

Без повторной установки профиль можно получить из уже сохранённых ключей:

```bash
umask 077
sudo bash warp-pipe-proxy.sh client-profile > client-sing-box.json
chmod 600 client-sing-box.json
```

Для ограничения прав уже в момент создания файла выполните перед экспортом `umask 077`. Сам установщик сохраняет профиль с правами 0600. Не публикуйте профиль: он содержит UUID доступа.

В локальной Wi-Fi-сети замените `outbounds[0].server` на IP ноутбука, а `server_port` — на опубликованный порт Podman. SNI, UUID, public key и Short ID менять не нужно. После импорта разрешите создание VPN-интерфейса и перезапустите клиент и браузер.

DNS клиента отправляет запросы через DoH Cloudflare по прокси. DNS на порту 53 перехватывается; AAAA-записи не подавляются. TUN принимает IPv4- и IPv6-трафик, оба направляются через VLESS. Для обращения к IPv6-адресам серверу нужен рабочий IPv6-маршрут в интернет; без него возможна ошибка `network is unreachable`.

Смена серверного DNS не исправляет уже переданный клиентом числовой IPv6-адрес. Файл нужно импортировать на клиенте; существующий профиль сам не обновится. Ссылка `vless://` не содержит этих DNS-правил. Проверка установщика проверяет доменный HTTPS-запрос, но не наличие внешней IPv6-связности.

## Ошибки и откат

Если этап применения или итоговая проверка завершились ошибкой, установщик пытается восстановить конфиги, клиентские результаты, настройки UFW и прежние состояния служб. Снимок создаётся после установки пакетов, непосредственно перед применением конфигураций.

Пакеты, APT-репозиторий, пользователь службы, созданный DNSSEC trust anchor и сгенерированные настройки/ключи сохраняются. Ошибка BBR не отменяет установку: скрипт пытается вернуть прежние параметры и записывает предупреждение.

При неполном восстановлении выводится `ROLLBACK INCOMPLETE` с путём резервной копии. Откат предусмотрен для ошибок и сигналов INT/TERM; SIGKILL и отключение питания обработать невозможно.

| Сообщение | Что проверить |
| --- | --- |
| `NET_ADMIN is required` | Разрешения контейнера на управление сетью |
| `Network sysctl is read-only` | Доступность записи `/proc/sys/net` в контейнере |
| `Unmanaged ... listener` | Какая служба занимает порт и как сохранить её доступность перед включением UFW |
| Ошибка DNSSEC trust anchor | Наличие `dns-root-data`, содержимое и права `/var/lib/unbound/root.key` |
| Ошибка проверки VLESS | Журнал `warp-pipe-proxy`, доступ в интернет, DNS и настройки Reality |
| `ROLLBACK INCOMPLETE` | Журнал установки, файлы резервной копии и фактическое состояние служб |

После устранения причины повторите запуск. Не удаляйте `/etc/warp-pipe-proxy/managed`: маркер позволяет продолжить частично завершённую установку. Не считайте установку успешной без завершающего сообщения `SUCCESS`.

## Проверки разработки

В Linux из каталога проекта:

```bash
bash -n warp-pipe-proxy.sh runtime.sh logging.sh
shellcheck -e SC1091 warp-pipe-proxy.sh runtime.sh logging.sh
python3 -B -m unittest test_configure test_runtime test_logging test_admin
```

Интеграционную проверку запускайте в отдельном Linux-окружении с Python 3, sing-box, curl и доступом в интернет:

```bash
python3 -B test_vless_integration.py
```

Она временно занимает порт 10443, использует системный DNS вместо Unbound и проверяет HTTPS через Reality с правильным и неверным UUID. Не запускайте её рядом с рабочим сервером на этом порту.

Проверки выполнялись на Ubuntu 24.04 в Podman, включая sing-box 1.14.4: прошли модульные тесты, ShellCheck, проверки конфигов Unbound/fail2ban и интеграционная проверка Reality. Полная установка с настоящими systemd, UFW и внешним клиентом на VPS пока не проверена. Проверка только ID Ubuntu не гарантирует совместимость со всеми версиями дистрибутива.

Контейнерный режим дополнительно проверяется тестами пропуска firewall/BBR, отсутствия зависимости от fail2ban и отката без изменения чужих настроек firewall.

## Обновление с версии с SOCKS

Повторите `sudo bash warp-pipe-proxy.sh install` (в контейнере добавьте `--container`). Установщик удалит публичный SOCKS-вход, его поля настроек и пароль, обновит ссылки подключения. UUID, ключи и порт VLESS сохраняются. Эти изменения входят в снимок отката; старый пароль может оставаться в закрытых резервных копиях.

В обычном режиме удаляются только правила UFW с точной меткой `warp-pipe-proxy SOCKS`, включая правила для ранее изменённых портов. Правила без этой метки, firewall провайдера и публикации Podman автоматически не меняются. В контейнерном режиме UFW не затрагивается: удалите старую публикацию `1081` при пересоздании контейнера и ненужные внешние разрешения самостоятельно.

На телефоне включите sing-box в VPN/TUN-режиме и отключите встроенный SOCKS-прокси Telegram. Проверка VLESS использует временный локальный прокси на `127.0.0.1`; публичного SOCKS-сервера больше нет.

## Диагностика и удобный экспорт

Все команды выполняются в установленной Ubuntu или внутри контейнера. `status` быстро проверяет службы и принадлежность порта, без сетевых запросов. `doctor` проверяет конфигурацию, DNS по UDP/TCP, прямой доступ по IPv4/IPv6 и HTTPS через временный VLESS-клиент. Он ничего не перенастраивает.

```bash
sudo bash warp-pipe-proxy.sh status
sudo bash warp-pipe-proxy.sh doctor
sudo bash warp-pipe-proxy.sh doctor --url https://ya.ru/
sudo bash warp-pipe-proxy.sh check --container --url https://ya.ru/
sudo bash warp-pipe-proxy.sh logs --follow
sudo bash warp-pipe-proxy.sh logs --since '10 minutes ago' --filter '172.64.'
```

`check --url` сначала выполняет обязательные проверки установки, затем диагностику сайта. В `doctor` HTTP 3xx/4xx/5xx означает полученный ответ, а не сбой транспорта. Перенаправления и ресурсы страницы не загружаются. Ошибка IPv6 выводится как предупреждение и сама по себе не делает диагностику неуспешной: у выбранного сайта может не быть AAAA, либо проблема может быть в DNS/маршруте. Команда не доказывает доступность всех IPv6-ресурсов или подключение телефона извне. Проверяйте также журнал клиента.

Для Podman можно экспортировать профиль с адресом ноутбука и внешним портом без редактирования JSON:

```bash
umask 077
sudo bash warp-pipe-proxy.sh client-profile --endpoint 192.168.1.10 --port 10443 > client-sing-box.json
```

`--endpoint` принимает IPv4/IPv6-адрес, включая частный адрес LAN. Меняются только адрес и порт в выводимом профиле; настройки сервера, SNI, UUID и ключи не изменяются. Вывод содержит секрет доступа, не публикуйте его. `--help` показывает доступные команды и параметры. `logs --filter` ищет буквальную подстроку, не регулярное выражение.

Реализация сервисных команд — `admin.py`, тесты — `test_admin.py`. Для проверки запускайте `python3 -B -m unittest test_configure test_runtime test_logging test_admin`.

## Команда в PATH

После успешной установки доступна команда `warp-pipe-proxy` из любой папки:

```bash
sudo warp-pipe-proxy status
sudo warp-pipe-proxy doctor --url https://ya.ru/
sudo warp-pipe-proxy logs --follow
sudo warp-pipe-proxy check --container
```

Запускатель расположен в `/usr/local/bin/warp-pipe-proxy`, а независимая копия шести рабочих скриптов — в `/usr/local/lib/warp-pipe-proxy`. Исходную папку после установки можно переместить или удалить. Настройки shell менять не требуется; если `/usr/local/bin` отсутствует в PATH, используйте полный путь к команде.

Для обновления кода повторите установку из новой исходной папки. `sudo warp-pipe-proxy install` повторно применяет уже установленную версию, не скачивает обновления; в контейнере обязательно добавляйте `--container`. Чужие файлы с совпадающими путями установщик не перезаписывает. Установка команды включена в откат конфигурации.


## Смена ключей VLESS

На установленном сервере выполните из обновлённой папки проекта:

```bash
sudo bash warp-pipe-proxy.sh rotate-keys
```

После обновления установленной CLI через `install` доступна также команда
`sudo warp-pipe-proxy rotate-keys`. В контейнере используется та же команда:
смена ключей не меняет firewall, fail2ban, DNS и настройки BBR.

Команда меняет UUID, ключевую пару Reality и Short ID, проверяет конфигурацию
и перезапускает только прокси. После успешного HTTPS-запроса через VLESS обновляет
`/etc/warp-pipe-proxy/client-sing-box.json` и `clients.txt`.
IP, порты и Reality SNI сохраняются. Все клиенты должны импортировать новый профиль;
старые подключения прерываются при перезапуске.

При ошибке применения или проверки восстанавливаются прежние файлы и служба.
Проверка требует доступа к тестовому HTTPS-сайту; его недоступность также вызывает откат.
Секреты не выводятся в журнал. Предыдущие ключи остаются в каталоге резервной копии
с доступом только root; путь выводится после завершения.


## QR-код VLESS в терминале

```bash
sudo bash warp-pipe-proxy.sh client-qr
```

Для телефона в одной Wi-Fi-сети с ноутбуком, где сервер работает в Podman:

```bash
sudo bash warp-pipe-proxy.sh client-qr --endpoint 192.168.1.10 --port 10443
```

Укажите IP ноутбука и опубликованный порт. Команда читает актуальные ключи,
в том числе после `rotate-keys`; настройки сервера не меняются.
QR содержит только VLESS-ссылку, без DNS/TUN-настроек JSON-профиля.
Не публикуйте QR: он предоставляет доступ к прокси. Разверните терминал,
чтобы изображение помещалось целиком.

Установщик устанавливает `qrencode` автоматически. Для существующей установки
можно установить его отдельно: `sudo apt-get install qrencode`.
После обновления CLI через `install` доступна короткая команда
`sudo warp-pipe-proxy client-qr`. QR и ссылка не записываются в журнал установщика.
