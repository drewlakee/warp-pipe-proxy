# Warp Pipe Proxy

> **Русский** · [English](README.en.md)

Установщик личного прокси VLESS Reality на Ubuntu. Трафик идёт через ваш сервер, сайты видят его IP. Установщик настраивает sing-box и создаёт ключи.

## Что настраивает установщик

При первом запуске установщик определяет публичный IPv4 и выбирает узел для рукопожатия Reality, проверив TLS 1.3 и HTTP/2. Если sing-box ещё не установлен, он добавляет официальный APT-репозиторий и устанавливает пакет.

| Компонент | Настройка по умолчанию |
| --- | --- |
| Прокси | Настраивает sing-box с VLESS Reality на `0.0.0.0:10443/TCP`. Служба `warp-pipe-proxy` запускается от отдельного системного пользователя и включается при загрузке. |
| DNS | Сервер разрешает имена через Unbound на `127.0.0.1:5353`. Полный клиентский JSON-профиль направляет DNS через прокси к `1.1.1.1` по HTTPS. |
| Ключи и доступ | Создаёт пару ключей Reality, Short ID и отдельный UUID для локальной проверки. Список устройств при первой установке пуст. Хранит учётные данные в `/etc/warp-pipe-proxy/credentials.json` с правами `0600`. По умолчанию клиентам закрыт доступ к внутренним адресам. |
| Защита SSH и сеть на VPS | Сохраняет правила уже активного UFW. Если firewall отсутствует, открывает порт прокси и TCP-порты SSH, затем включает UFW. Fail2ban блокирует источник на час после пяти неудачных входов по SSH за десять минут. При поддержке ядром включает TCP BBR. При запуске с `--container` установщик пропускает UFW, fail2ban и BBR. |
| Проверка и восстановление | Проверяет локальный DNS и выполняет HTTPS-запрос через VLESS. Сохраняет журнал в `/var/log/warp-pipe-proxy-installer/` и резервную копию в `/var/lib/warp-pipe-proxy-installer/`. При сбое применения пытается восстановить управляемые файлы и службы. |

## Установка

В примерах ниже показаны фрагменты вывода. Время, адреса и пути запусков могут отличаться. В ссылках и профилях секреты заменены метками в угловых скобках.

Понадобятся чистая Ubuntu с systemd, права root или sudo и публичный IPv4 для подключения из интернета. Разрешите входящий **TCP 10443** в firewall провайдера. Серверу нужен доступ к APT, HTTPS и DNS (исходящие TCP и UDP 53).

На сервере или внутри контейнера скачайте проект.

```bash
git clone https://github.com/drewlakee/warp-pipe-proxy.git
cd warp-pipe-proxy
```

<details>
<summary>Пример вывода</summary>

```text
Cloning into 'warp-pipe-proxy'...
```

При успехе `cd` ничего не печатает.

</details>

### VPS

Запустите установщик на VPS.

```bash
sudo ./warp-pipe-proxy.sh install
```

<details>
<summary>Пример вывода</summary>

```text
[SUCCESS] Installed command: /usr/local/bin/warp-pipe-proxy
[SUCCESS] SUCCESS: VLESS Reality configured
```

</details>

Установщик автоматически проверяет firewall; дополнительных параметров для этого нет.

- **UFW уже активен:** все его правила и политики сохраняются, в том числе ограничения SSH по IP. Новое разрешение для прокси тоже не добавляется: при необходимости разрешите TCP 10443 в существующей политике. Локальная проверка установки не подтверждает доступность этого порта извне.
- **Firewall отсутствует:** установщик получает порты из конфигурации `sshd`, разрешает их и порт прокси, затем включает UFW с запретом прочих входящих соединений. Перед этим проверяются слушающие службы; системные DHCP-клиенты учитываются отдельно.
- **UFW выключен, но содержит сохранённые правила, либо обнаружена другая политика iptables/nftables:** установка останавливается до применения конфигурации с объяснением. Существующую политику нужно сначала проверить самостоятельно; установщик не активирует её и не создаёт второй firewall поверх неё.

Повторная установка сохраняет активный UFW, даже если он был первоначально настроен этим проектом. При изменении порта прокси обновите его разрешение в своей политике самостоятельно.

### Контейнер

Используйте Ubuntu-контейнер с systemd в качестве PID 1. При создании опубликуйте порт `-p 10443:10443/tcp` и разрешите его в firewall хоста. Внутри контейнера выполните команду установки.

```bash
sudo ./warp-pipe-proxy.sh install --container
```

<details>
<summary>Пример вывода</summary>

```text
[SUCCESS] SUCCESS: VLESS Reality configured
[WARN] CONTAINER MODE: proxy checks passed; UFW, fail2ban and BBR were not managed
```

</details>

Добавляйте `--container` при каждом запуске `install` и `check`. Firewall настраивается на хосте.

## Подключить устройство

На сервере создайте профиль телефона. Для QR-кода, ссылки и JSON всегда указывайте `--device ИМЯ`, даже если устройство одно.

```bash
sudo warp-pipe-proxy device-add --device phone
```

<details>
<summary>Пример вывода</summary>

```text
[SUCCESS] Credential change completed: device-add
```

</details>

**QR или ссылка.** Отсканируйте QR в клиенте VLESS Reality или импортируйте ссылку. Оба варианта дают доступ к прокси.

```bash
sudo warp-pipe-proxy client-qr --device phone
```

<details>
<summary>Пример вывода</summary>

```text
VLESS QR contains access credentials. Keep it private. DNS/TUN settings require the JSON profile.
```

Следом терминал рисует QR-код с данными телефона.

</details>

```bash
sudo warp-pipe-proxy client-config --device phone
```

<details>
<summary>Пример вывода</summary>

```text
VLESS Reality:
vless://<UUID>@203.0.113.10:10443?encryption=none&flow=xtls-rprx-vision&security=reality&sni=www.microsoft.com&fp=chrome&pbk=<PUBLIC_KEY>&sid=<SHORT_ID>&type=tcp#vps-reality
```

</details>

**Профиль sing-box.** Для системного туннеля (TUN) и DNS через прокси сохраните JSON, перенесите файл на устройство и импортируйте его в sing-box.

```bash
umask 077
sudo warp-pipe-proxy client-profile --device phone > phone.json
```

<details>
<summary>Результат в phone.json</summary>

```text
      "type": "vless",
      "tag": "proxy",
      "server": "203.0.113.10",
      "server_port": 10443,
      "uuid": "<UUID>",
```

Это фрагмент объекта `outbounds[0]`. Обе команды при успехе ничего не выводят в терминал. Команда `umask` задаёт права для новых файлов, а `>` записывает JSON в `phone.json`.

</details>

При подключении к контейнеру по Wi-Fi добавьте к `client-qr` или `client-profile` параметры `--endpoint 192.168.1.10 --port 10443`, подставив LAN-адрес хоста и опубликованный порт.

## Смена ключей устройств

После успешной ротации **каждому активному устройству потребуется новый профиль**. Перезапуск прокси прерывает текущие соединения. Старые QR-коды, ссылки и JSON больше не подходят для входа.

```bash
sudo warp-pipe-proxy rotate-keys
```

```text
VLESS Reality authenticated HTTPS request passed
[SUCCESS] Credential change completed: rotate-keys
[INFO] Export and import new profiles on every active device
[INFO] Previous credentials are retained in the root-only backup: /var/lib/warp-pipe-proxy-installer/<RUN>
```

Меняются общая пара ключей Reality, Short ID и индивидуальный UUID каждого активного устройства. Имена устройств сохраняются. Например, `phone` и `laptop` останутся активными, а отозванный `old-phone` останется отозванным.

После сообщения об успехе выведите новый QR для `phone` или экспортируйте JSON для `laptop` командами из раздела [«Подключить устройство»](#подключить-устройство), указав имя нужного устройства в `--device`. Замените профиль в приложении и переподключитесь. Повторять `device-add` не нужно.

<details>
<summary>Если проверка после перезапуска не прошла</summary>

```text
[WARN] Rolling back managed configuration and service states
[SUCCESS] Managed configuration and service states restored
```

При успешном откате прежние профили снова работают. Сообщение `ROLLBACK INCOMPLETE` означает, что нужно проверить журнал и резервную копию.

</details>

## Управление и диагностика

| Задача | Команда | Пример вывода (фрагмент) |
| --- | --- | --- |
| Отозвать старый телефон | `sudo warp-pipe-proxy device-revoke --device old-phone` | `[SUCCESS] Credential change completed: device-revoke` |
| Список устройств | `sudo warp-pipe-proxy device-list` | `laptop	active`<br>`old-phone	revoked`<br>`phone	active` |
| Службы и порт | `sudo warp-pipe-proxy status` | `Proxy service: PASS`<br>`DNS service: PASS`<br>`VLESS TCP port 10443: PASS` |
| Проверить DNS и VLESS | `sudo warp-pipe-proxy check` | `VLESS Reality authenticated HTTPS request passed` |
| Проверить в контейнере | `sudo warp-pipe-proxy check --container` | `[WARN] Container mode: UFW and fail2ban checks skipped; host firewall must protect published ports` |
| Проверить сайт | `sudo warp-pipe-proxy doctor --url https://example.com` | `Direct IPv4 transport: PASS`<br>`VLESS transport passed; inspect the HTTP status above` |
| Активность всех устройств | `sudo warp-pipe-proxy activity` | `phone  12s ago  84`<br>`tablet  -  0` |
| Недавние обращения телефона | `sudo warp-pipe-proxy activity --device phone --since "10 minutes ago"` | `2026-11-26 14:32:08  TCP  example.com:443` |
| Новые обращения телефона | `sudo warp-pipe-proxy activity --device phone --follow` | `2026-11-26 14:32:10  UDP  203.0.113.24:443` |
| Следить за журналом | `sudo warp-pipe-proxy logs --follow` | `… inbound/vless[vless-reality]: [phone] inbound connection to example.com:443` |
| Справка | `warp-pipe-proxy --help` | `usage: warp-pipe-proxy.sh [-h] [--container] …` |

По умолчанию `activity` показывает время последнего обращения и число запросов на соединение для каждого профиля за последний час по данным журнала. В сводку входят и отозванные профили, и устройства с нулём запросов. Служебные проверки `@probe` пропускаются. С параметром `--device` видны время (UTC), протокол и адрес назначения, который передал клиент. Один сайт может породить несколько запросов. Режим `--follow` показывает новые события. Добавьте `--since`, чтобы сначала увидеть историю.

Для отключения одного устройства достаточно `device-revoke`. Работающая служба перезапустится, остальные устройства смогут подключиться с прежними профилями. Если служба уже остановлена, отзыв применяется без её запуска. Команда `status` проверяет службы и порт локально; доступность извне проверьте с устройства.

**Отзыв фиксируется после локальной проверки и применения конфигурации.** Ошибка последующего запроса к внешнему сайту выводит предупреждение, но устройство остаётся отозванным и команда успешно завершается. Это отличается от добавления устройства и ротации: у них неуспешная обязательная проверка по-прежнему вызывает откат.

Если во время отзыва не удалось записать конфигурацию или запустить службу, команда завершается ошибкой и оставляет прокси остановленным с отключённым автозапуском. Старый доступ автоматически не восстанавливается. Проверенный вариант без отозванного устройства сохраняется в `/var/lib/warp-pipe-proxy-installer/<RUN>/revocation/`, а `/etc/warp-pipe-proxy/revocation-pending.json` сохраняет состояние незавершённого отзыва. Если `credentials.json` уже обновлён, повторная установка создаст конфигурацию из текущих отозванных credentials. Если запись самих credentials не состоялась, установщик откажется запускать прокси со старыми ключами: сначала нужно применить **проверенный файл из `revocation/credentials.json` указанного запуска**, сохранив права `0600`, затем повторить установку. Прежнюю копию до отзыва использовать нельзя. До завершения этой операции новые изменения устройств запрещены. Сначала проверьте причину ошибки в журнале; маркер вручную не удаляйте.

Если продолжать работу прокси не требуется, `uninstall` разрешён и при незавершённом отзыве. Он окончательно удалит данные проекта, включая ключи, маркер и все копии отзыва. Состав удаления описан в разделе [«Удаление»](#удаление).

## Настройки и обновление

Исходные настройки сервера хранятся в `/etc/warp-pipe-proxy/settings.json`. Изменяйте этот файл от root и применяйте изменения командой `sudo warp-pipe-proxy install` (в контейнере — с `--container`). Установщик заново создаёт и проверяет конфигурации служб перед их применением. Ручные изменения сгенерированных файлов, например `/etc/sing-box/config.json`, при повторном применении будут перезаписаны. Назначение остальных файлов описано в разделе [«Расположение файлов»](#расположение-файлов).

| Поле `settings.json` | Значение и ограничения |
| --- | --- |
| `public_ip` | Публичный IPv4 сервера, который попадёт в клиентские профили. |
| `reality_host` | Домен узла рукопожатия Reality. При первой установке выбирается после проверки TLS 1.3 и HTTP/2. |
| `vless_port` | TCP-порт прокси; по умолчанию `10443`. |
| `dns_port` | Порт локального Unbound на `127.0.0.1`; по умолчанию `5353`. |
| `allowed_private_subnets` | Необязательный список разрешённых внутренних подсетей, например `["192.168.50.0/24"]`. По умолчанию исключений нет; добавленное исключение действует для всех устройств. |

Оба порта должны быть разными целыми числами в диапазоне `1024..65535`; на VPS они также не должны совпадать с портами SSH. После изменения порта прокси обновите разрешение в уже активном firewall, firewall провайдера и, при необходимости, публикацию порта контейнера. После изменения публичного адреса, порта или узла Reality заново экспортируйте клиентские профили. Параметры `--endpoint` и `--port` доступны у `client-profile` и `client-qr` и меняют только выдаваемый профиль, а не настройки слушающей службы; `client-config` их не принимает.

При первом создании `settings.json` можно передать через `sudo env` переменные `VPS_PUBLIC_IP` (свой публичный IPv4 вместо автоопределения) и `VPS_REALITY_HOST` (домен или список кандидатов через пробел). Например:

```bash
sudo env VPS_REALITY_HOST=www.microsoft.com ./warp-pipe-proxy.sh install
```

Если `settings.json` уже существует, эти переменные его не переопределяют: дальнейшие изменения вносите в сам файл. Для устройств используйте `device-add`, `device-revoke` и `rotate-keys`; `credentials.json` вручную не редактируйте. Повторная установка поверх существующей сохраняет UUID и ключи Reality и сама их не ротирует. Новая установка после `uninstall` создаёт новые ключи. Режим `--container` нужно указывать при каждом `install` и `check`.

Для обновления выполните `git pull --ff-only` в каталоге проекта и повторите команду установки из выбранного раздела выше. При обновлении со старой версии с единым UUID существующие подключения сохраняют доступ. Этот UUID доступен по явному имени `--device default`. Укажите нужные внутренние подсети до обновления.

<details>
<summary>Примеры вывода при обновлении и повторном применении</summary>

```text
$ git pull --ff-only
Already up to date.

$ sudo warp-pipe-proxy install
[SUCCESS] SUCCESS: VLESS Reality configured
```

В примере локальная копия уже актуальна. После скачивания новой версии запускайте установщик из каталога проекта, как показано выше. Вариант `sudo warp-pipe-proxy install` применяет уже установленную версию.

</details>

## Расположение файлов

### Настройки, ключи и состояние установщика

Все файлы в следующей таблице находятся в **`/etc/warp-pipe-proxy/`**. Каталог принадлежит root и создаётся с правами `0700`, его файлы — с правами `0600`. `settings.json` и `credentials.json` служат исходными данными для генерации конфигурации; остальные файлы создаёт и обновляет установщик.

| Файл в `/etc/warp-pipe-proxy/` | Назначение |
| --- | --- |
| `settings.json` | Публичный IP, порты, узел Reality и исключения для внутренних подсетей. Это файл для изменения серверных параметров. |
| `credentials.json` | Приватный и публичный ключи Reality, Short ID, служебный UUID и реестр устройств с их UUID и отзывами. Управляется командами устройств; содержит секреты доступа. |
| `managed`, `installed` | Маркеры управляемой установки и её успешного завершения. Удаляются вместе со всем каталогом при `uninstall`. |
| `summary.json`, `tls-check.txt` | Сводка настроек последней успешной установки и вывод первоначальной проверки узла Reality. Это диагностические файлы, не входные настройки. |
| `ownership.json` | Контрольные суммы принадлежащих проекту файлов прокси, установленной команды и дополнительных конфигураций. Используется для проверки принадлежности файлов перед удалением. |
| `revocation-pending.json` | Маркер незавершённого отзыва с контрольными суммами проверенного варианта credentials. Блокирует новые изменения устройств и применение старых ключей; полное удаление остаётся доступным. |
| `clients.txt`, `client-sing-box.json` | Экспорты совместимости со старой установкой с профилем `default`; в новой установке автоматически не создаются. Содержат доступ к прокси. Для текущих устройств используйте команды экспорта с `--device`. |

Служебные маркеры и контрольные суммы вручную не меняйте. Порядок работы с копиями и незавершёнными операциями приведён в разделах [«Управление и диагностика»](#управление-и-диагностика) и [«Удаление»](#удаление). После успешного `uninstall` весь `/etc/warp-pipe-proxy/` удалён.

### Конфигурации служб и установленная команда

| Путь | Что находится и как управляется |
| --- | --- |
| `/etc/sing-box/config.json` | Сгенерированная конфигурация сервера с приватным ключом; `root:warp-pipe-proxy`, `0640`. Каталог `/etc/sing-box/` имеет права `0750`. Пересоздаётся из settings/credentials при установке и изменении устройств. |
| `/etc/unbound/unbound.conf.d/warp-pipe-proxy.conf` | Сгенерированная настройка локального DNS; root, `0644`. При необходимости установщик также создаёт DNSSEC trust anchor `/var/lib/unbound/root.key` из `dns-root-data`, с владельцем `unbound` и правами `0644`. |
| `/etc/fail2ban/jail.d/warp-pipe-proxy.local` | Сгенерированная SSH jail с обнаруженными портами `sshd`; root, `0644`. В режиме контейнера не создаётся и не изменяется. |
| `/etc/systemd/system/warp-pipe-proxy.service` | Сгенерированный unit службы; root, `0644`. Запускает sing-box от пользователя `warp-pipe-proxy` с зависимостью от Unbound. |
| `/usr/local/bin/warp-pipe-proxy` | Команда запуска; root, `0755`. Обращается к установленной копии проекта, поэтому исходный checkout для обычного управления не нужен. |
| `/usr/local/lib/warp-pipe-proxy/` | Рабочая копия shell/Python-модулей установщика и маркер `.managed`; каталог `0755`, файлы root с правами `0644`. Обновляется при установке из checkout. |
| `/var/lib/warp-pipe-proxy/` | Рабочий каталог и домашний каталог системного пользователя `warp-pipe-proxy`. Ключи и настройки хранятся отдельно в `/etc/warp-pipe-proxy/`. |
| `/etc/apt/sources.list.d/warp-pipe-proxy-sagernet.sources` | Описание официального APT-репозитория sing-box; root, `0644`. Добавляется, если sing-box ещё не установлен; принадлежавший проекту файл удаляется при `uninstall`. |
| `/etc/apt/keyrings/sagernet.asc` | Общий ключ репозитория sing-box; root, `0644`. Может использоваться другими APT-источниками, поэтому сохраняется после удаления проекта. |
| `/etc/sysctl.d/90-warp-pipe-proxy.conf`, `/etc/modules-load.d/warp-pipe-proxy.conf` | Сохранённые настройки `fq`/BBR и загрузки `tcp_bbr`. Создаются при успешном включении этой оптимизации вне контейнера. |
| `/etc/ufw/`, `/etc/default/ufw` | Общая конфигурация UFW. Установщик инициализирует её только при отсутствии существующей политики; активный firewall сохраняет свои правила. |

### Журналы, копии и временные файлы

`<RUN>` — идентификатор запуска из времени UTC и PID, например `20261126T120000Z-1234`. Каталоги журналов и копий доступны только root (`0700`); журналы и отдельные файлы восстановления создаются с правами `0600`. Вложенные копии системных файлов могут сохранять прежние права, но находятся внутри закрытого каталога.

| Путь | Назначение |
| --- | --- |
| `/var/log/warp-pipe-proxy-installer/<RUN>.log` | Вывод установки, проверки или изменения устройств. `uninstall` удаляет весь этот каталог и не создаёт свой журнал. Журнал самого прокси находится в общем systemd journal: `sudo warp-pipe-proxy logs` или `sudo journalctl -u warp-pipe-proxy`. |
| `/var/lib/warp-pipe-proxy-installer/<RUN>/` | Копия конкретной операции. При установке содержит исходные системные файлы с их путями, например `etc/…`. Копии могут содержать прежние приватные ключи и UUID. |
| `/var/lib/warp-pipe-proxy-installer/<RUN>/transaction/` | Файлы для отката применения конфигурации. Соседние `paths`, `active` и `enabled` описывают пути, активность и автозапуск служб. |
| `/var/lib/warp-pipe-proxy-installer/<RUN>/revocation/` | Проверенная конфигурация без отозванного устройства для завершения отзыва при сбое. Содержит новые settings/credentials и сгенерированные файлы. |
| `/var/lib/warp-pipe-proxy-installer/{stage.*,rotate.*}` | Временные каталоги подготовки конфигурации и изменения credentials. Удаляются при обычном завершении операции, включая обработанный сбой. |
| `/var/lib/warp-pipe-proxy-uninstalling.json` | Временный маркер удаления без ключей и профилей: хранит контрольные суммы принадлежащих проекту файлов и состояние общих служб. Позволяет продолжить прерванную очистку; после успеха удаляется. |
| `/run/lock/warp-pipe-proxy.lock` | Блокировка, которая не позволяет одновременно изменять установку или экспортировать промежуточное состояние credentials. |

Копии для отката установки и завершения отзыва сохраняются, пока проект установлен. `uninstall` удаляет весь `/var/lib/warp-pipe-proxy-installer/`, включая старые копии, секреты в них и оставшиеся временные каталоги. Новую копию перед удалением команда не создаёт.

## Удаление

Перед удалением старой установки обновите checkout и один раз успешно примените эту версию установщика. Это создаёт `/etc/warp-pipe-proxy/ownership.json` с контрольными суммами принадлежащих проекту файлов. Без сведений о принадлежности автоматическое удаление отказывается угадывать владельца файлов. Старый формат метаданных может не учитывать дополнительные конфигурации: такие файлы сохраняются с предупреждением. Если сервер нужно немедленно остановить без обновления, используйте `sudo systemctl disable --now warp-pipe-proxy`; ключи останутся на месте.

```bash
sudo warp-pipe-proxy uninstall
```

**Команда удаляет проект вместе с его данными, без создания новой копии.** Она проверяет принадлежность управляемых файлов, останавливает и отключает службу прокси, затем выполняет очистку. Если принадлежность файла нельзя подтвердить или управляемый файл изменён вручную, сначала нужно разобрать указанный конфликт; чужие конфигурации команда не удаляет. Незавершённый отзыв устройства не препятствует окончательному удалению.

| Что удаляется | Состав |
| --- | --- |
| Настройки, ключи и профили | Весь `/etc/warp-pipe-proxy/`, включая credentials, настройки, экспорты совместимости, контрольные суммы и маркер незавершённого отзыва. |
| Прокси и установленная команда | `/etc/sing-box/config.json`, unit `warp-pipe-proxy.service`, `/usr/local/bin/warp-pipe-proxy`, весь `/usr/local/lib/warp-pipe-proxy/` и `/var/lib/warp-pipe-proxy/`. Каталог `/etc/sing-box/` удаляется, если после удаления конфигурации он пуст. |
| Старые копии и журналы установщика | Весь `/var/lib/warp-pipe-proxy-installer/` и `/var/log/warp-pipe-proxy-installer/`. Нового снимка или журнала удаления не создаётся. |
| Принадлежащие проекту дополнительные файлы | Его конфигурации Unbound и fail2ban, файлы автозагрузки BBR и sysctl, APT-источник `warp-pipe-proxy-sagernet.sources`. Удаляются только файлы с подтверждённой принадлежностью проекту. |
| Разрешения порта прокси в UFW | Только правила исходного вида с точным комментарием `warp-pipe-proxy Reality`. Правила администратора, в том числе для того же порта, сохраняются. Изменённые правила и разрешения портов, которые теперь используются SSH, сохраняются с предупреждением. |

**Сохраняются общие компоненты хоста:** системные пакеты и системный пользователь `warp-pipe-proxy`, общие настройки и данные Unbound/fail2ban, ключ `/etc/apt/keyrings/sagernet.asc`, действующие политики UFW и правила SSH. Удаление не сбрасывает firewall и не выключает его. Файлы постоянной настройки BBR удаляются, но параметры уже работающего ядра остаются до перезагрузки или явного изменения администратором; прежние значения установщик не восстанавливает. Записи самого прокси в общем systemd journal отдельно не удаляются: очистка общего журнала затронула бы и другие службы.

После успешного удаления в перечисленных каталогах проекта больше нет настроек и ключей. При новой установке ключи и пустой список устройств создаются заново: устройства нужно добавить и выдать им новые профили. Ранее выданные QR-коды, ссылки и JSON не подойдут. Сохранённые изменения общих конфигураций хоста могут потребовать проверки перед новой установкой. Уже активный UFW остаётся активным, а его существующую политику установщик сохраняет: если разрешение порта прокси было удалено, добавьте нужное разрешение самостоятельно. Исходный checkout и файлы, которые вы сами экспортировали или скопировали за пределы перечисленных каталогов, остаются у вас.

Если удаление прервано, повторите его из сохранённого checkout:

```bash
sudo ./warp-pipe-proxy.sh uninstall
```

Для продолжения используется только временный `/var/lib/warp-pipe-proxy-uninstalling.json` со сведениями о незавершённой очистке, без ключей и профилей. Установка блокируется, пока очистка не завершена. После успеха этот маркер тоже удаляется; повторный вызов из checkout завершится без изменений, если проект уже удалён. Команда `uninstall` доступна и при незавершённом отзыве устройства: она окончательно удаляет все связанные данные.
